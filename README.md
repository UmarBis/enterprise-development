# FitnessClub — «Фитнес-клуб»

Лабораторные работы по курсу [«Разработка корпоративных приложений»](https://github.com/itsecd/enterprise-development).

**Вариант 35** — предметная область «Фитнес-клуб», СУБД MS SQL Server, брокер сообщений Kafka.

## Предметная область

В базе данных фитнес-клуба содержится информация о записях клиентов на персональные занятия к тренерам.

- **Person** — базовый класс с персональными данными, общими для клиента и тренера: номер паспорта, имя, фамилия, пол (`Gender` — перечисление), дата рождения. Полное имя (`FullName`) вычисляется как «Фамилия Имя».
- **Client** — клиент фитнес-клуба: телефон, дата начала и дата окончания абонемента.
- **Trainer** — тренер: специализация (сущность-справочник `Specialization`), стаж работы.
- **Specialization** — справочник специализаций тренеров.
- **Booking** — запись клиента на занятие: клиент, тренер, дата и время занятия, название зала, признак пробного посещения.

Идентификаторы сущностей — `Guid`. Свойства объявлены через `init` (неизменяемы после конструирования), обязательные поля помечены `required`. `Booking` ссылается на клиента и тренера по их идентификаторам.

## Структура решения

- `src/FitnessClub.Domain` — сущности предметной области, перечисления, интерфейсы репозиториев (паттерн Repository), генератор тестовых данных.
- `src/FitnessClub.Contracts` — DTO с валидационными атрибутами и интерфейсы сервисов.
- `src/FitnessClub.Application` — реализация сервисов: маппинг сущностей в DTO, бизнес-логика, аналитические запросы.
- `src/FitnessClub.Infrastructure.InMemory` — реализации репозиториев поверх коллекций в памяти.
- `src/FitnessClub.ServiceDefaults` — общие настройки телеметрии и resilience.
- `src/FitnessClub.Api` — REST API сервер (ASP.NET Core, .NET 10).
- `tests/FitnessClub.Tests` — unit-тесты аналитических запросов (xUnit v3).

Хранение данных абстрагировано за интерфейсами репозиториев: переход с коллекций
в памяти на СУБД выполняется заменой реализаций в конфигурации DI.
Контроллеры, сервисы и репозитории используют асинхронные контракты.
За клиентов, тренеров, специализации и занятия отвечают отдельные сервисы,
аналитические запросы реализованы в `AnalyticsService`.

## Лабораторная работа №1 «Классы»

Объектная модель предметной области и unit-тесты аналитических запросов:
данные хранятся в памяти, не менее 10 экземпляров каждого класса.

1. Тренеры, стаж работы которых не менее 5 лет.
2. Проверка доступности зала для записи в данный момент.
3. Клиенты с просроченным абонементом, упорядоченные по ФИО.
4. Занятия за текущий месяц в выбранном зале.
5. Топ-5 наиболее популярных тренеров.

## Лабораторная работа №2 «Сервер»

REST API сервер, реализующий базовые CRUD-операции над сущностями
и предоставляющий результаты аналитических запросов. Данные хранятся в памяти
в виде коллекций.

### Запуск

```bash
dotnet run --project src/FitnessClub.Api

CRUD-эндпоинты
Сущность	                       Методы
Клиенты	       GET/POST /api/clients, GET/PUT/DELETE /api/clients/{id}
Тренеры	       GET/POST /api/trainers, GET/PUT/DELETE /api/trainers/{id}
Специализации	 GET/POST /api/specializations, GET/PUT/DELETE /api/specializations/{id}
Занятия	       GET/POST /api/bookings, GET/PUT/DELETE /api/bookings/{id}

       Запрос	                                     Эндпоинт

Клиенты с просроченным абонементом	GET /api/clients/expired
Занятия за текущий месяц в зале   	GET /api/bookings/current-month?hallName=...
Топ-5 популярных тренеров	          GET /api/trainers/popular?count=5

Запуск тестов:
  dotnet test
