# FitnessClub — «Фитнес-клуб»

Лабораторные работы по курсу [«Разработка корпоративных приложений»](https://github.com/itsecd/enterprise-development).

**Вариант 35** — предметная область «Фитнес-клуб», СУБД MS SQL Server, брокер сообщений Kafka.

## Предметная область

В базе данных фитнес-клуба содержится информация о записях клиентов на персональные занятия к тренерам.

- **Person** — базовый класс с персональными данными, общими для клиента и тренера: номер паспорта, имя, фамилия, пол (`Gender` — перечисление), дата рождения. Полное имя (`FullName`) вычисляется как «Фамилия Имя».
- **Client** — клиент фитнес-клуба: телефон, дата начала и дата окончания абонемента.
- **Trainer** — тренер: специализация (сущность-справочник `Specialization`), стаж работы.
- **Specialization** — справочник специализаций тренеров.
- **Booking** — запись клиента на занятие: клиент, тренер, дата и время занятия, название зала, признак пробного посещения.

Идентификаторы сущностей — `Guid`. Свойства объявлены через `init` (неизменяемы после конструирования), обязательные поля помечены `required`. `Booking` ссылается на клиента и тренера по их идентификаторам.

## Структура решения

- `src/FitnessClub.Domain` — сущности предметной области, перечисления, интерфейсы репозиториев (паттерн Repository), генератор тестовых данных.
- `src/FitnessClub.Contracts` — DTO с валидационными атрибутами и интерфейсы сервисов.
- `src/FitnessClub.Application` — реализация сервисов: маппинг сущностей в DTO, бизнес-логика, аналитические запросы.
- `src/FitnessClub.Infrastructure.InMemory` — реализации репозиториев поверх коллекций в памяти.
- `src/FitnessClub.ServiceDefaults` — настройки OpenTelemetry, health checks, service discovery и HTTP resilience.
- `src/FitnessClub.Api` — REST API сервер (ASP.NET Core, .NET 10).
- `tests/FitnessClub.Tests` — unit-тесты аналитических запросов (xUnit v3).

Хранение данных абстрагировано за интерфейсами репозиториев: переход с коллекций
в памяти на СУБД выполняется заменой реализаций в конфигурации DI.
Контроллеры, сервисы и репозитории используют асинхронные контракты.
Проверка существования связанных сущностей выполняется в Application; удаление
клиентов, тренеров и специализаций, на которые ссылаются другие записи,
возвращает конфликт HTTP 409.
За клиентов, тренеров, специализации и занятия отвечают отдельные сервисы,
аналитические запросы реализованы в `AnalyticsService`.

## Лабораторная работа №1 «Классы»

Объектная модель предметной области и unit-тесты аналитических запросов:
данные хранятся в памяти, не менее 10 экземпляров каждого класса.

1. Тренеры, стаж работы которых не менее 5 лет.
2. Проверка доступности зала для записи в данный момент.
3. Клиенты с просроченным абонементом, упорядоченные по ФИО.
4. Занятия за текущий месяц в выбранном зале.
5. Топ-5 наиболее популярных тренеров.

## Лабораторная работа №2 «Сервер»

REST API сервер, реализующий базовые CRUD-операции над сущностями
и предоставляющий результаты аналитических запросов. Данные хранятся в памяти
в виде коллекций.

### Запуск

```bash
dotnet run --project src/FitnessClub.Api
```
Сервер доступен на https://localhost:<port>. Swagger (OpenAPI) доступен по пути /swagger.
Проверки состояния ServiceDefaults доступны по `/health` и `/alive` в Development.

Ожидаемые ошибки возвращаются в формате ProblemDetails: 400 — некорректный запрос,
404 — отсутствующая сущность, 409 — конфликт связей, 500 — непредвиденная ошибка.

CRUD-эндпоинты
  Сущность	                           Методы
Клиенты	           GET/POST /api/clients, GET/PUT/DELETE /api/clients/{id}
Тренеры	           GET/POST /api/trainers, GET/PUT/DELETE /api/trainers/{id}
Специализации	     GET/POST /api/specializations, GET/PUT/DELETE /api/specializations/{id}
Занятия	           GET/POST /api/bookings, GET/PUT/DELETE /api/bookings/{id}


Аналитические эндпоинты
          Запрос	                                       Эндпоинт
Тренеры со стажем не менее 5 лет	  GET /api/analytics/trainers/experienced?minYears=5
Доступность зала для записи	        GET /api/analytics/halls/{hallName}/availability?at=...
Клиенты с просроченным абонементом	GET /api/analytics/clients/expired
Занятия за текущий месяц в зале	    GET /api/analytics/halls/{hallName}/bookings?year=...&month=...
Топ-5 популярных тренеров	          GET /api/analytics/trainers/top?count=5


Запуск тестов
```bash
dotnet test
```

## Лабораторная работа №3 «ORM»

В третьей лабораторной работе InMemory-хранилище заменено на Microsoft SQL Server
с использованием Entity Framework Core 10.

### Реализованные изменения

- Добавлен проект `FitnessClub.Infrastructure.SqlServer` с контекстом `FitnessClubDbContext`.
- Реализованы SQL Server-репозитории для клиентов, тренеров, специализаций и записей на занятия.
  Контракты репозиториев и сервисный слой сохранены, поэтому контроллеры и бизнес-логика
  не зависят от конкретной СУБД.
- Настроено отображение модели `Person` по стратегии TPC: данные клиентов и тренеров
  хранятся в отдельных таблицах `Clients` и `Trainers`.
- Настроены внешние ключи от тренеров к специализациям и от записей к клиентам/тренерам,
  ограничения уникальности паспортных номеров и названий специализаций, индексы для аналитических запросов.
- Добавлена миграция `20261120010000_InitialCreate`.
- При запуске API выполняется `Database.MigrateAsync()`. Если таблица специализаций пуста,
  база заполняется исходным набором из `ClubDataSeeder` (12 клиентов, 12 тренеров,
  10 специализаций и 26 записей).
- В `FitnessClub.AppHost` добавлен ресурс SQL Server и база `fitnessclub`.
  Aspire запускает SQL Server и API, передавая приложению строку подключения.

### Структура хранения

| Таблица | Назначение |
|---|---|
| `Clients` | Клиенты и сведения об абонементах |
| `Trainers` | Тренеры, стаж и ссылка на специализацию |
| `Specializations` | Справочник специализаций |
| `Bookings` | Записи клиентов на занятия |

### Запуск через .NET Aspire

Требуются .NET SDK 10 и Docker Desktop (или совместимый Docker Engine).

Из корня решения:

```bash
dotnet run --project src/FitnessClub.AppHost
```

Откройте адрес панели Aspire, который появится в терминале. В панели будут доступны
ресурсы SQL Server и `fitnessclub-api`. При первом запуске Aspire создаст контейнер SQL Server,
а API применит миграцию и заполнит базу начальными данными.

Swagger доступен по адресу API, путь `/swagger`.

### Запуск API отдельно

Для запуска без Aspire укажите строку подключения в `src/FitnessClub.Api/appsettings.json`
или через переменную окружения `ConnectionStrings__fitnessclub`. Например:

```text
Server=localhost,1433;Database=FitnessClub;User Id=sa;Password=<YOUR_PASSWORD>;TrustServerCertificate=True;Encrypt=False
```

SQL Server должен быть предварительно запущен и доступен по указанному адресу.

### Работа с миграциями

В проект добавлен локальный манифест инструмента `dotnet-ef`. Восстановите инструмент:

```bash
dotnet tool restore
```

Применить существующие миграции:

```bash
dotnet ef database update --project src/FitnessClub.Infrastructure.SqlServer --startup-project src/FitnessClub.Api
```

Создать следующую миграцию после изменения модели:

```bash
dotnet ef migrations add <MigrationName> --project src/FitnessClub.Infrastructure.SqlServer --startup-project src/FitnessClub.Api
```

Миграции также применяются автоматически при старте API.

### Unit-тесты

Тестовый проект и InMemory-реализации сохранены для изолированных unit-тестов
бизнес-логики. Для запуска:

```bash
dotnet test
```

В API зарегистрирована SQL Server-инфраструктура; InMemory-проект больше не используется
сервером в качестве основного хранилища.
